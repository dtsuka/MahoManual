# 注釈エディタ全画面モーダル化 実装指示書

## 1. 目的

マニュアル編集画面のプレビューまたはMarkdownライブプレビューに表示された注釈付き画像を選択したとき、マニュアル編集画面を破棄せず、注釈エディタをほぼ全画面のモーダルとして開く。

この変更により、次の状態を保ったまま注釈を編集できるようにする。

- 未保存のMarkdown本文
- CodeMirrorの選択範囲とUndo履歴
- 左右ペインそれぞれのスクロール位置
- ライブプレビューの有効・無効
- 画像挿入パネルなど、マニュアル編集画面内の一時的なUI状態

対象はマニュアル編集画面から画像を開く導線だけとする。プロジェクト画面、画像取り込み直後、URL直接入力などから開く既存の注釈エディタは、引き続き独立した全画面ページとして利用できるようにする。

## 2. この文書の位置づけ

この文書は実装指示書であり、実装コードではない。実装開始時は `docs/PLAN.md` の末尾に未完了の新Phaseを追加し、`AGENTS.md` のTDD手順に従って、テスト作成・失敗確認・コミット・実装・成功確認・コミットの順で進めること。

既存仕様との優先関係は次のとおり。

1. `docs/SPEC.md` のデータモデル、座標系、レンダリング、ライブ同期仕様
2. `DESIGN.md` のGUIデザインシステムと既存e2e依存事項
3. 本書のモーダル表示・画面状態保持に関する追加仕様

本対応では注釈JSON、Markdownフェンス、coreレンダラー、座標系、APIのデータ形式を変更しない。

## 3. 完成時の利用フロー

### 3.1 モーダルを開く

マニュアル編集画面で、次のいずれかの注釈付き画像を選択するとモーダルを開く。

- 右ペインの完成プレビュー内にある `figure[data-mm-annotation]`
- CodeMirrorライブプレビュー内にある注釈付き画像

画面全体を別ページへ切り替えず、マニュアル編集画面を背面に残す。背面は表示状態を維持するが、モーダル表示中はクリック、キー入力、フォーカス移動を受け付けない。

### 3.2 注釈を編集する

モーダル内では既存の注釈エディタ機能をすべて利用可能にする。

- オブジェクトの追加、選択、移動、リサイズ、削除
- Undo / Redo
- クロップ、整列、レイヤー操作
- 前の注釈・次の注釈への移動
- 外部変更の検知と競合解決
- PNG出力
- 画像ID変更。ただし後述のMarkdown未保存時の制限に従う
- 保存

前後の注釈へ移動してもモーダル表示を維持し、マニュアル編集画面を再マウントしない。

### 3.3 モーダルを閉じる

モーダル内の左上に、独立ページの「戻る」とは区別できる「閉じる」操作を表示する。

注釈に未保存変更がない場合は直ちに閉じる。未保存変更がある場合は、既存の未保存移動バナーを再利用し、次の3択を表示する。

- 保存して閉じる
- 破棄して閉じる
- キャンセル

Escキーも同じ閉じる要求として扱う。ただし、次の一時操作が進行中の場合は、その操作のキャンセルを優先し、1回目のEscでモーダルを閉じない。

- インラインテキスト編集
- ビジュアルクロップ
- 線・矢印・矩形の作成途中
- 競合解決

背景クリックでは閉じない。広い作業画面での誤操作による編集破棄を避けるためである。

閉じた後は、モーダルを開いた画像またはライブプレビュー内の画像操作へフォーカスを戻し、元のスクロール位置を維持する。

## 4. 表示仕様

### 4.1 モーダル外枠

デスクトップでは画面四辺に12〜16px程度の余白を残す、ほぼ全画面のオーバーレイとする。

- 背景オーバーレイ: `slate-950`相当の半透明色
- モーダル本体: 白背景、`slate-200`相当の境界線、控えめな影
- 角丸: デスクトップのみ。狭い画面では角丸を外して画面端まで使用する
- 高さ: `100dvh`を基準にし、モーダル本体から外へページスクロールを発生させない
- z-index: 既存のツールレール、通知バナー、ツールチップより外側のモーダルレイヤーを最上位にする

過度な開閉アニメーションは付けない。追加する場合も `DESIGN.md` に従い、150ms以内の色・不透明度変化だけとし、`prefers-reduced-motion` では停止する。

### 4.2 注釈エディタの埋め込み表示

現在の注釈エディタは `h-screen` を前提としているため、表示方法を明示的に切り替えられるようにする。

例:

```ts
type AnnotationEditorPresentation = "page" | "modal";
```

- `page`: 既存どおり `h-screen`
- `modal`: モーダル本体に追従する `h-full min-h-0`

モーダル対応のためにキャンバス、ツールレール、右パネルの寸法やヒット領域を変更しない。右パネルは既存の `w-80` を基本とし、狭い画面への対応が必要な場合は本対応内で独自に縮小せず、別要件として扱う。

### 4.3 既存デザインとの整合

- ボタンや入力は `packages/app/src/components/ui.tsx` の既存コンポーネントを使う
- 操作色は青、注釈色はマゼンタという `DESIGN.md` の分離を維持する
- 既存の `data-testid` と、独立ページにおける「戻る」「未保存」などのテキスト依存を壊さない
- モーダル専用要素には安定した `data-testid` を追加する

推奨する新規test id:

- `annotation-modal`
- `annotation-modal-backdrop`
- `annotation-modal-close`

## 5. URL・履歴仕様

### 5.1 モーダル用URL

マニュアル編集画面のモーダル状態は、次のクエリーパラメータで表現する。

```text
/projects/:project/manual?annotation=:id
```

Reactのローカルstateだけで管理してはならない。URLで状態を表すことで、再読み込み、ブラウザの戻る・進む、URL共有時の挙動を定義可能にする。

### 5.2 既存URLの維持

次の既存URLは廃止・リダイレクトしない。

```text
/projects/:project/annotations/:id
```

このURLでは注釈エディタを独立ページとして表示する。プロジェクト画面の注釈一覧、画像取り込み直後、既存の外部リンクは当面このURLを使用してよい。

### 5.3 履歴操作

- 画像クリックでモーダルを開くときは履歴を1件追加する
- モーダル内の前・次移動と画像ID変更は、現在のモーダル履歴を置換する
- マニュアル画面から開いたモーダルを閉じるときは、原則としてブラウザ履歴を1件戻す
- `?annotation=` 付きURLを直接開いた場合など、戻り先がマニュアル画面である保証がない場合は、クエリーだけを削除して `/manual` へ置換する
- 不正または存在しないannotation IDでは、モーダル内に読み込みエラーと閉じる操作を表示し、マニュアル編集画面は維持する

履歴由来か直接表示かを判別するため、画像クリック時の `navigate` にモーダル起点を示す `location.state` を付けてもよい。ただし、再読み込み後はstateがなくても安全に閉じられるフォールバックを持つこと。

## 6. 状態管理とデータ同期

### 6.1 ManualEditorを再マウントしない

モーダル表示中も `ManualEditor` とCodeMirrorのインスタンスを維持する。次の実装は禁止する。

- 条件分岐で `ManualEditor` の代わりに `AnnotationEditor` をreturnする
- モーダル表示時にCodeMirrorを破棄して、閉じるときに再生成する
- 見た目だけをオーバーレイにして、内部では `/annotations/:id` のページへ全面遷移する

背面の無効化には `inert` を優先し、補助的に `aria-hidden` とポインターイベント制御を使う。CodeMirrorのDOMを削除してはならない。

### 6.2 注釈保存後のプレビュー更新

注釈JSONの保存後、背面の完成プレビューとCodeMirrorライブプレビューを最新状態へ更新する。

現在の `ManualEditor` は `manual.md` の変更だけを監視しているため、注釈保存時には次のいずれかの明示的な更新経路を追加する。

1. `AnnotationEditor` の保存成功コールバックから、現在の `markdownRef.current` を使ってプレビューを即時再生成する
2. `annotations/*.json` のSSEイベントを `ManualEditor` が受け取り、現在のMarkdownを使ってプレビューを再生成する

どちらの場合も、Markdown本文をディスクから再読込してはならない。未保存のMarkdownを正本としてプレビューを生成すること。保存のたびにCodeMirror自体を再生成しない。

表示更新は注釈保存成功後に行い、破棄して閉じた場合は不要とする。連続イベントが発生しても既存のシーケンス番号とデバウンス規則で古い応答を破棄する。

### 6.3 Markdown未保存中の画像ID変更

画像ID変更はannotationファイルだけでなく、ディスク上の `manual.md` の `src` も書き換える。背面のCodeMirrorに未保存変更がある状態で実行すると、ディスクとGUIのMarkdownが分岐するため、次の仕様とする。

- `ManualEditor` が未保存の場合、モーダル内の画像ID変更を無効化する
- 無効理由として「先にマニュアル本文を保存してください」と表示する
- 注釈自体が未保存の場合にID変更を無効化する既存仕様も維持する
- `ManualEditor` が保存済みの場合はID変更を許可する
- 変更成功後は `manual.md` を再取得してCodeMirrorへ反映し、モーダルのクエリーIDを置換する
- ID変更後もモーダルを閉じず、選択・編集を継続できるようにする

将来、未保存Markdownとの安全な局所マージを実装するまで、この制限を外してはならない。

### 6.4 未保存注釈と外部変更

既存の次の仕組みをそのまま利用する。

- `useAnnotationDocument` のdirty判定
- 未保存移動バナー
- `beforeunload`
- SSEによる外部変更検知
- 3-wayマージとオブジェクト単位の競合解決

モーダルの閉じる操作がこれらを迂回して、直接コンポーネントをアンマウントしてはならない。閉じる要求は必ず `AnnotationEditor` 内の既存ナビゲーション判定と同じ経路を通す。

## 7. キーボード・アクセシビリティ

モーダルは少なくとも次を満たすこと。

- モーダル本体に `role="dialog"` と `aria-modal="true"` を付ける
- `{project} / {annotationId}` の見出しを `aria-labelledby` で参照する
- 開いた直後のフォーカス位置を明示する
- Tab / Shift+Tabのフォーカスをモーダル内へ閉じ込める
- 背面のマニュアル編集UIを支援技術とキーボード操作の対象から外す
- 閉じた後、起点となった画像操作へフォーカスを戻す
- 右ペインの画像をEnterまたはSpaceでも開けるようにする
- CodeMirrorライブプレビューの画像もキーボードで開ける状態を維持する
- Escは一時操作のキャンセルを優先し、その後に未保存確認付きの閉じる操作として働く

右ペインのcore由来figure DOMへGUI専用のフォーカス属性を追加する場合、納品HTMLやcoreレンダラーの出力は変更しない。

## 8. 実装対象ファイルと責務

実装時は、少なくとも次のファイルを確認する。

### `packages/app/src/components/ManualEditor.tsx`

- ManualEditorを保持したまま背面を無効化
- 注釈保存後のプレビュー再生成
- 起点要素とフォーカス復帰の管理
- Markdown dirty状態を注釈エディタへ伝達

### `packages/app/src/components/AnnotationEditor.tsx`

- `page` / `modal` の表示モード
- モーダル時の閉じる表示と閉じる要求
- 既存の未保存ナビゲーション処理との統合
- Escの優先順位
- 保存成功通知
- ホスト側Markdownがdirtyの場合のID変更制限
- 見出しIDなど、ダイアログのアクセシブルネームに必要な情報

### `packages/app/src/components/AnnotationEditorModal.tsx`（新規推奨）

- backdropとモーダル外枠
- dialog属性
- フォーカストラップ
- bodyスクロール抑止
- 背面クリックで閉じない制御
- 開閉時のフォーカス移動

モーダル固有処理を `ManualEditor.tsx` にすべて直書きしない。ダイアログ外枠とフォーカス管理は分離する。

### `packages/app/src/App.tsx`

- `/annotations/:id` の独立ページ表示を維持
- 独立ページとモーダルで共通の `AnnotationEditor` を利用
- 既存の画像取り込み後ナビゲーションを壊さない

### `packages/app/tests/e2e/editor.spec.ts`

- 既存の「figureクリックで注釈エディタへ遷移」テストを、モーダル仕様へ更新
- 本書の受け入れシナリオを追加

core、CLI、MCP、サーバーAPIにモーダル都合のロジックを追加しない。既存APIで不足が確認された場合は、先に理由を明記して指示書とPLANを更新する。

## 9. TDD実装順

実装開始時は、次の順序を `docs/PLAN.md` の新Phaseへチェックボックスとして追加する。

### 9.1 モーダル基本導線

1. e2eテストを追加し、失敗を確認する
   - 右プレビューの画像クリックで `annotation-modal` が表示される
   - URLが `/manual?annotation=:id` になる
   - `md-editor` がDOM上に残り、同じCodeMirrorインスタンスの編集内容が保たれる
   - モーダルを閉じるとクエリーが消え、Markdownの未保存内容が残る
2. テストのみをコミットする
3. モーダル外枠、クエリー状態、埋め込み表示を実装する
4. テスト成功を確認して実装をコミットする

### 9.2 閉じる・履歴・未保存保護

1. e2eテストを追加し、失敗を確認する
   - clean状態の閉じる
   - dirty状態で閉じると未保存バナーが表示される
   - キャンセルでモーダルを維持する
   - 保存して閉じる
   - 破棄して閉じる
   - ブラウザの戻る・進む
   - `?annotation=` 付きURLの直接表示と安全な閉じる
2. テストのみをコミットする
3. 既存の `requestNavigation` を再利用して実装する
4. テスト成功を確認して実装をコミットする

### 9.3 プレビュー同期とID変更

1. e2eテストを追加し、失敗を確認する
   - 注釈を保存すると、モーダルを閉じた後の右プレビューへ変更が反映される
   - ライブプレビューにも変更が反映される
   - 未保存Markdownがプレビュー再生成時に失われない
   - Markdown dirty中は画像ID変更が無効になる
   - Markdown clean時のID変更で、CodeMirror内の `src` とモーダルURLが更新される
2. テストのみをコミットする
3. 保存通知、プレビュー再生成、ID変更制限を実装する
4. テスト成功を確認して実装をコミットする

### 9.4 キーボード・フォーカス・回帰

1. e2eテストを追加し、失敗を確認する
   - Enter / Spaceで画像からモーダルを開ける
   - Tab / Shift+Tabがモーダル外へ出ない
   - Escの一時操作キャンセルと閉じるの優先順位
   - 閉じた後に起点へフォーカスが戻る
   - 前・次移動でもモーダルを維持する
   - 独立URL `/annotations/:id` は従来どおり全画面で開く
   - プロジェクト画面の注釈一覧と画像取り込み直後の導線が壊れていない
2. テストのみをコミットする
3. アクセシビリティと回帰対応を実装する
4. `pnpm -r test` と対象e2eを実行し、成功後に実装をコミットする

テストを通すための待機時間延長は禁止する。モーダル表示、プレビュー更新、フォーカス復帰は、固定sleepではなくDOM状態またはURLを待って検証する。

## 10. 受け入れ基準

以下をすべて満たしたときに完了とする。

- マニュアル編集画面の右プレビューとライブプレビューの両方からモーダルを開ける
- モーダル表示中もManualEditorとCodeMirrorが再マウントされない
- 未保存Markdown、選択、Undo履歴、スクロール位置、ライブプレビュー状態が保持される
- 注釈エディタの既存機能がモーダル内でも利用できる
- 注釈の未保存変更を、閉じる・Esc・履歴操作で誤って失わない
- 注釈保存後、現在の未保存Markdownを使った最新プレビューが表示される
- Markdown未保存中の画像ID変更が安全に禁止される
- 前・次移動とID変更後もモーダル表示を維持する
- URL再読み込みとブラウザの戻る・進むが定義どおり動作する
- `/projects/:project/annotations/:id` の独立ページ表示が維持される
- モーダルにdialog属性、フォーカストラップ、フォーカス復帰、キーボード起動がある
- デスクトップ表示でキャンバス、ツールレール、右パネルが欠けず、ページ全体に不要なスクロールが出ない
- 既存の `data-testid`、注釈JSON、Markdown、納品HTML/PDF/PNGの出力が変わらない
- `pnpm -r test` が成功する
- 対象Playwright e2eが成功する
- 実画面で、開く・編集・保存・閉じる・再表示を確認する

## 11. 対象外

本対応には次を含めない。

- プロジェクト画面の注釈一覧をモーダル化すること
- 画像取り込み直後の注釈エディタをモーダル化すること
- 注釈エディタの右パネルをレスポンシブに再設計すること
- 注釈ツール、オブジェクト、ショートカットの追加や仕様変更
- 注釈JSON、Markdownフェンス、API、coreレンダラーの変更
- 自動保存の導入
- Markdown未保存中の画像ID変更を可能にする高度なマージ処理
- モーダル外観を理由とした既存GUI全体のリデザイン

## 12. 実装上の判断原則

迷った場合は、次の順で判断する。

1. 未保存データを失わない
2. ManualEditorとCodeMirrorを再マウントしない
3. 既存の注釈エディタ機能と独立URLを壊さない
4. 現在の未保存Markdownをプレビューの正本にする
5. モーダル専用の分岐をcoreやサーバーへ持ち込まない
6. 見た目より、履歴・フォーカス・未保存確認の一貫性を優先する
